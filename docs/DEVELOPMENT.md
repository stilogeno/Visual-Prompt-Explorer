# Development Guide

This guide is for contributors who want to run, modify, or extend the Visual Prompt Explorer.

## Requirements

- **Node.js** 18+ (project uses v25.7.0)
- **npm** for package management
- Python 3 (only needed to regenerate style data with `update_data.py`)

## Running Locally

```bash
npm install
npm run dev
```

Opens at `http://localhost:5173` with hot module replacement.

## Available Scripts

| Command | Purpose |
|---------|---------|
| `npm run dev` | Start Vite dev server with HMR |
| `npm run build` | Production build to `dist/` |
| `npm run preview` | Preview production build locally |

## Regenerating Style Data

The gallery data lives in `app/data.js` as a global `galleryData` array. It is generated by `update_data.py` from the source dataset.

```bash
python3 update_data.py
```

This rewrites `app/data.js`. After regenerating, hard-refresh the browser.

### Style Object Shape

Each entry in `galleryData`:

```js
{
  id: "0a0d648c7b36",
  prompt: "cinematic, dramatic lighting, film grain, ...",
  folder: 1,
  post_count: 42,
  avg_favs: 16,
  avg_score: 0.92,
  uniqueness_score: 0.7
}
```

- `id` — matches image filename `images/{folder}/{id}.webp`
- `prompt` — the descriptive style prompt
- `folder` — image subfolder number
- `avg_favs` — community likes (converted to star rating: `likes ÷ 4`, capped at 5)

## Adding a New Style

1. Add the preview image to `images/{folder}/{id}.webp`
2. Add a matching entry to the dataset used by `update_data.py` (or directly to `galleryData` in `app/data.js`)
3. Regenerate `app/data.js`
4. Rebuild the gallery manifest: `python3 scripts/build_gallery_manifest.py` (if it exists)
5. Reload the gallery

## Adding a New Page

1. Create `src/pages/YourPage.jsx`
2. Add a route in `src/App.jsx`: `<YourPage path="/your-page" />`
3. Add a nav entry in `src/components/Header.jsx` PAGES array

## Code Style

- **Preact + JSX** for components
- **Signals** for reactive state (avoid `useState` for shared state)
- **CSS files** per component (imported in component files)
- **No TypeScript** (plain JSX)
- Keep components small and focused
- Use `signal.value` reads in computed properties for proper reactivity

## Building for Production

```bash
npm run build
```

Output goes to `dist/`. The PWA plugin generates a service worker and manifest automatically.

To serve locally:

```bash
npx serve dist
# or
python3 -m http.server 8080 -d dist
```

## Cache-Busting

The Vite build handles cache-busting via content hashing in filenames. No manual versioning needed.

## Service Worker

During development, the service worker may serve stale files. Use hard refresh (Cmd+Shift+R) or unregister in DevTools while iterating.
